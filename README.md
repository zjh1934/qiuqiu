# 球球

### 手机上的字看不清？让手机念给你听

一个小球浮在屏幕上，随时待命：

| 你想干什么 | 怎么做 |
|---|---|
| **字太小，看不清** | **按住球不放** → 屏幕立刻放大，手指挪到哪，看到哪 |
| **懒得看，想听** | **轻点一下球**（球会变绿）→ **再点屏幕上的字** → 手机从那一句开始念 |
| **不想听了** | **再轻点一下球** → 马上停 |

装完之后**开启一次无障碍，以后再也不用管**，球一直都在。

## ⚙️ 装完必做一步：打开无障碍开关

这一步**只做一次**。不做的话球不会出来。

1. 打开手机的 **设置**
2. 找到 **无障碍**（有的手机叫"辅助功能"）
3. 找到 **球球** → 把开关 **打开**

各品牌位置：

| 手机 | 路径 |
|---|---|
| 华为 / 荣耀 | 设置 → 辅助功能 → 无障碍 → 球球 |
| 小米 / 红米 | 设置 → 更多设置 → 无障碍 → 球球 |
| OPPO / 一加 / realme | 设置 → 其他设置 → 无障碍 → 球球 |
| vivo / iQOO | 设置 → 快捷与辅助 → 无障碍 → 球球 |
| 三星 | 设置 → 辅助功能 → 已安装的应用程序 → 球球 |
| 原生安卓 / 谷歌 Pixel | 设置 → 系统 → 无障碍 → 球球 |

打开之后，屏幕右边就出现一个小球。

## 五种手势（记住两个就够用）

| 操作 | 效果 |
|---|---|
| **轻点球** | 球变绿，进入"准备读字"状态 |
| **再点屏幕上的字** | 从那一句开始往下念 |
| **朗读中轻点球** | 停止朗读 |
| **按住球不动** | 放大；手指挪动，画面跟着走；松手恢复 |
| **拖动球** | 把球挪到顺手的位置 |

**闲置 2.5 秒**，球会自动变淡，不挡视线；碰一下就恢复。

## 常见问题

**Q：球没出来？**
先确认「设置 → 无障碍」里「球球」的开关是打开的。再打开「球球」APP，首页会有一行字告诉你现在卡在哪一步。

**Q：提示"语音引擎还在初始化"？**
刚装好第一次用，等一两秒再点就好了。不是故障。

**Q：点了字没反应 / 说"这里没读到文字"？**
有些 APP（比如游戏、纯图片的界面）不向无障碍服务提供文字，这种读不到是正常的。系统界面、微信、新闻类 APP 都能正常读。

**Q：朗读的声音不好听 / 想换声音？**
打开「球球」APP → 声音页，可以挑引擎和音色。

**Q：会上传我的隐私吗？**
不会。这个软件**不联网、不上传任何内容**，你在屏幕上读到的字不会离开你的手机。

## 💻 给开发者

### 编译

工程是标准 Gradle 结构：根目录有 `settings.gradle`，代码在 `app/` 模块。
**没有提交 gradle wrapper**（一直用 AIDE 构建，用不到）。

**AIDE（本项目实际在用的方式）**
1. 用 AIDE 打开工程根目录（含 `build.gradle` / `settings.gradle` 的那层）
2. 直接 Build

**Android Studio**
wrapper 没入库，先补上：
1. 工程根目录执行 `gradle wrapper`（需本地 Gradle 6.7+），或让 Studio 打开时自动生成
2. 根目录 `build.gradle` 补上 AGP classpath，例如 4.2.2
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`

依赖：`compileSdkVersion 30` / `minSdkVersion 24` / `targetSdkVersion 29`。
无第三方运行时依赖，单元测试用 JUnit 4.13.2。

### 源码结构

```
ComboService.java   唯一服务：手势分发 + 状态机 + 保活通知
BallController.java 手势判定（拖动 / 按住放大 / 轻点）
BallView.java       球的绘制，四态（待命/放大/选取/朗读）
ZoomController.java 系统放大控制
TextGrabber.java    抓字：多窗口取根 → 单趟收集 → 阅读顺序 → 精确到句 → 续读
TextLayout.java     纯排版逻辑（阅读顺序 / 断句），无 Android 依赖，可单测
TtsManager.java     TTS 引擎与音色管理
Prefs.java          设置读写
MainActivity.java   三个 Tab 的界面
```

### 抓字的关键点

参考了 AutoX / Assists 等同类方案的踩坑经验：

- **多窗口遍历**：`getRootInActiveWindow()` 只在窗口内容变化时才取得到数据，
  经常返回 null，也拿不到弹窗 / 输入法 / 分屏另一半。所以走 `getWindows()`
  按 layer 从高到低扫，哪个窗口点得到字就用哪个。
- **可见性过滤**：用 `isVisibleToUser()` 过滤掉滚出屏幕的节点，
  否则会把列表里看不见的几十条也读出来。
- **节点数上限**：病态节点树（超长列表）会把主线程拖死，设了 10000 的上限；
  字符位置请求的官方上限是 20000。
- **阅读顺序**：不能只按 `(top, left)` 排，多列布局会读乱序
  （右列第二行混进左列第一行之间）。做法是先把垂直重叠过半的归成一行，
  行内再按 left 排。
- **单趟遍历**：收集只走一遍树，避免 O(n²) 和双倍 IPC。
- **节点回收**：`AccessibilityNodeInfo` 是有限系统资源，漏 `recycle()`
  会让后续 `getChild()` 直接抛异常，表现为"读一会儿就抓不到字了"。
