# 看得清

### 手机上的字看不清？按住放大，点一下念给你听。

一个小球常驻在屏幕边上。不换手机、不改系统设置、不记复杂手势。

| 你想干什么 | 怎么做 |
|---|---|
| **字太小，看不清** | **按住球** → 画面放大，手指挪到哪就看到哪 |
| **想让它念** | **轻点球**（球变绿）→ **点屏幕上那段字** → 从这句开始念 |
| **不想听了** | **再轻点一下球** |

装完之后**开一次无障碍，以后不用管**，球一直都在。

---

## 这是给谁做的

- 眼睛花了、看小字费劲的爸妈和长辈
- 低视力、弱视、术后视力不佳的朋友
- 看十几分钟就眼睛酸、需要"少看多听"的人
- 以及照顾他们的家人

它是给**还看得见、但看得很吃力**的人做的，不是给全盲朋友的 ——
完全看不见的话，系统自带的 TalkBack 更合适。

不需要学任何复杂操作，就**点一下**和**按住**两个动作。

---

## 五个手势

| 操作 | 效果 |
|---|---|
| **轻点球** | 球变绿，进入"准备读字"状态 |
| **再点屏幕上的字** | 从那一句开始，念到这一屏结束 |
| **朗读中轻点球** | 停止朗读 |
| **按住球不动** | 放大；手指挪动，画面跟着走；松手恢复 |
| **拖动球** | 把球挪到顺手的位置 |

**闲置 2.5 秒**，球会自动变淡，不挡视线；碰一下就恢复。

每一步都有**震动**回应：进选字态两下短震、开始朗读一下稍长、读不到字一记长震。
看不清球有没有变色的时候，靠手感确认。不想要就在「球」页关掉。

## 三个真实场景

**① 微信里孩子发来一大段话**
字号已经调到最大还是费劲。点球 → 点第一句 → 它从这句一路念到这一屏结束。
眼睛歇着，耳朵听着。

**② 药盒上的说明书，字比蚂蚁还小**
按住球，屏幕放大三倍，手指挪到"用法用量"那一行，看清了松手。

**③ 短信验证码、快递单号**
数字最怕看错。点球 → 点那串数字 → 听一遍，比看三遍准。

## 能调什么

打开 App，四个标签页，都在屏幕最底下。

**朗读页**：换语音引擎、换音色、调语速（0.5 ~ 2.0）、调音调、试听一句、停止。
听不清就调慢，一般 0.8 左右最舒服。

**放大页**：放大倍率（1.5 ~ 5.0 倍）、按住多久算放大（120 ~ 600 毫秒）、
放大时球不变大（建议开）。

**球页**：球大小（36 ~ 88）、不透明度、闲置时变多淡、松手自动贴边、
点按时震一下（可关）、7 种球颜色。

**联系页**：作者的微信二维码、微信号，一键复制。

每页底下都有「恢复默认」，调乱了点一下就好。

## 常见问题

**Q：球没出来？**
先确认「设置 → 无障碍」里「看得清」是打开的。再打开 App，首页那行字会直接告诉你卡在哪一步
（服务没运行 / 球没加上 / 开关是关的）。

**Q：提示"语音引擎还在初始化"？**
刚装好第一次用，等一两秒。不是故障。

**Q：点了字说"这里没读到文字"？**
- 确认点**在字上**，不是旁边的空白
- 有些 APP（游戏、纯图片、部分视频界面）不向无障碍服务提供文字，读不到是正常的
- 系统界面、微信、短信、新闻类、浏览器一般都能读

**Q：放大之后字更糊了？**
放大是把屏幕上的像素拉开，不是重新排版，所以边缘会毛。这是系统放大的固有代价。
想要"又大又清楚"，用朗读。

**Q：朗读声音不好听 / 太快太慢？**
App → **朗读** 页：换引擎、换音色、调语速和音调，旁边有"恢复默认 1.00"。

**Q：会上传我的隐私吗？**
不会。**没有申请网络权限**，代码里也没有任何网络调用。
屏幕上读到的字只在内存里活几秒，读完就没了。

## 权限

| 权限 | 干什么用 | 能不能关 |
|---|---|---|
| **无障碍** | 在屏幕上画球、读屏幕上的字、控制放大 | 不行，这是唯一途径 |
| **震动** | 点中时震一下 | 能，在「球」页关掉 |
| **前台服务 + 通知** | 让系统知道它还在工作，别随手杀掉 | 通知可以划掉 |
| **显示在其他应用上层** | 极少数机型的无障碍浮层加不上时的兜底 | 正常机型用不到 |
| **存储（仅安卓 10）** | 把诊断日志导到「下载」目录 | 不导出日志就用不到 |

**没有"网络"这一项。** 这个权限根本没申请，所以从系统层面就传不出去。

日志只记软件自己的状态（"按下了""开始朗读了"），**不记你读到的任何文字**。

## 给开发者

### 工程结构

标准 Gradle 结构：根目录 `settings.gradle`，代码在 `app/` 模块。
**没有提交 gradle wrapper**（一直用 AIDE 构建，用不到）。

```
ComboService.java    唯一服务：手势分发 + 状态机 + 取字覆盖层 + 保活通知
BallController.java  手势判定（拖动 / 按住放大 / 轻点），放大时的坐标与缩放补偿
BallView.java        球的绘制，四态（待命/放大/选取/朗读）
ZoomController.java  系统放大控制（倍率 / 中心点 / 屏幕↔内容坐标换算）
TextGrabber.java     抓字：多窗口取根 → 单趟收集 → 阅读顺序 → 精确到句 → 续读
TextLayout.java      纯排版逻辑（阅读顺序 / 断句），无 Android 依赖，可单测
TtsManager.java      TTS 引擎与音色管理，长文本切段，按会话号丢弃过期回调
Haptics.java         触觉反馈：四种节奏对应四种状态
Prefs.java           设置读写（唯一出入口）
MainActivity.java    四个 Tab 的界面（朗读/放大/球/联系）
```

### 抓字的关键点

参考了 AutoX / Assists 等同类方案的踩坑经验：

- **多窗口遍历**：`getRootInActiveWindow()` 只在窗口内容变化时才取得到数据，
  经常返回 null，也拿不到弹窗 / 输入法 / 分屏另一半。所以走 `getWindows()`
  按 layer 从高到低扫，哪个窗口点得到字就用哪个。
- **可见性过滤**：用 `isVisibleToUser()` 过滤掉滚出屏幕的节点，
  否则会把列表里看不见的几十条也读出来。
- **节点数上限**：病态节点树（超长列表）会把主线程拖死，设了 10000 的上限；
  字符位置请求的官方上限是 20000。
- **阅读顺序**：不能只按 `(top, left)` 排，多列布局会读乱序
  （右列第二行混进左列第一行之间）。做法是先把垂直重叠过半的归成一行，
  行内再按 left 排。
- **单趟遍历**：收集只走一遍树，避免 O(n²) 和双倍 IPC。
- **节点回收**：`AccessibilityNodeInfo` 是有限系统资源，漏 `recycle()`
  会让后续 `getChild()` 直接抛异常，表现为"读一会儿就抓不到字了"。
- **窗口类型**：Android 只有一个 `TYPE_SYSTEM` 同时代表状态栏和导航栏，
  没有 `TYPE_STATUS_BAR` / `TYPE_NAVIGATION_BAR`，写错编译不过。

### 放大的坐标

系统放大的映射（内容坐标 C → 屏幕位置 P，放大中心 K，倍率 s）：

```
P = S/2 + s × (C − K)
```

要的是"手指移到哪，就看到屏幕上那个位置的放大内容"——手指是**不动点**：

```
K = fx − (fx − S/2) / s
```

推论：在不动点处，内容坐标 = 屏幕坐标。所以球的窗口位置直接就是 `fx − 球宽/2`。

**不能写成 `K = K0 − ΔF/s`**，那是"手指抓着内容不动"，画面会相对手指静止，看着像不会动。

### 朗读的两个坑

- **单次上限 4000 字**：`TextToSpeech.getMaxSpeechInputLength()`，超了 `speak()`
  直接返回 ERROR。长文章必须切段排队，否则"球变橙但一点声音都没有"。
- **打断会产生假回调**：新朗读 flush 掉上一句时，被 flush 那句也会回调 `onDone`。
  不区分就会"刚读两个字就跳回待命"。每段带会话号，回调时比对，过期的丢掉。

### 自检

开发机没有 JDK / Android SDK 时用 Python 镜像兜底：

```bash
python verify_all.py     # 跑三遍，全绿
```

| 脚本 | 检查什么 |
|---|---|
| `verify_structure.py` | 括号配对、跨文件符号解析、import 缺失 |
| `verify_textlayout.py` | 阅读顺序、断句逻辑的镜像 |
| `verify_grabber.py` | 抓字全流程镜像（收集 / 排序 / 拼装 / 回收） |
| `verify_textcompare.py` | 续读去重：只比相等，不比包含 |
| `verify_speak.py` | 长文本切段：不吞字、不重字、每段不超上限 |

> ⚠️ 这些脚本**只验逻辑，不验 API**。
> 2.0 曾经写过 `AccessibilityWindowInfo.TYPE_STATUS_BAR`——几套自检全绿，
> 真编译一次才发现常量根本不存在。**有 JDK 就必须真跑一次 javac。**

### 构建

**AIDE（这个项目一直在用的方式）**

无第三方运行时依赖，单元测试用 JUnit 4.13.2。

## 已知限制

- **读不到图片里的字**：没有 OCR。纯图片、扫描件、游戏界面读不出来。
- **依赖 APP 向无障碍暴露文字**：有些 APP（尤其自绘引擎）不提供文字节点。
- **放大是像素放大**，字会变毛边，不会重新排版。
- **部分国产 ROM 的省电策略**会自动关闭无障碍服务，需要手动设为"不限制"。
- **`targetSdkVersion 29`**：为 AIDE 构建保留。上架应用商店需要提到 33+，
  并补 `foregroundServiceType`、`POST_NOTIFICATIONS` 等声明。
